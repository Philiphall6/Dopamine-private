# A15 / 23A355: AGX notification-bound empty packet v2

Revision:
`self-page-write-v1+agx-notification-vtable-v2+rtkit-mmio-disabled-v1`.

Target: iPhone14,2, iOS 26.0.1, build 23A355 only.

## Runtime findings through v4

ABI v3 passed the live `device+0x268=0x40/0x40` contract and issued selector
25 exactly once. The call returned `0xe00002bc`, while the firmware pool,
command queue, backend pointer, dispatch state, command index, buffer and
identity pointers remained unchanged. The connection then closed cleanly and
the phone did not restart.

This result proves the `0x40` wrapper ABI but not packet consumption.

The one v4 device run then created the notification queue successfully with
selector 14: it returned ID `1`, a writable `0x4000` user mapping, and a stable
registry object. It stopped at the vtable guard before selector 24 or selector
25. The observed unslid vtable was `0xfffffff007e479a8`, while v4 had the
incorrect expectation `0xfffffff007e42f28`. The owned connection closed
cleanly and the phone did not restart.

## Exact-image explanation

The retained kernelcache has SHA-256
`8867208c59bfa426611c36fcfe570ffc41cc75ee293472fe7197860d0c5223f1`.
The selector-25 wrapper at `0xfffffff009f1acec` accepts the G14P contract and
calls the batch routine at `0xfffffff009f49254`. That routine initializes its
return value to `0xe00002bc`, reads `queue+0x428` at
`0xfffffff009f492b4`, and branches directly to its return when the field is
zero. The backend and parser are therefore unreachable in the observed v3
state.

The normal prerequisite is closed statically:

- Selector 14 wrapper `0xfffffff009f1ab60` accepts scalars `{256, 32}`, returns
  a `0x10` structure, and registers an `IOGPUNotificationQueue` in
  `client-table+0x90`.
- Selector 14 reaches the notification factory at `0xfffffff009f555f0`. Its
  metaclass allocator slot `0xfffffff007e47ab0` decodes to
  `0xfffffff009f554c4`, which installs instance vtable
  `0xfffffff007e479a8`. This is the exact value observed in v4.
- The notification memory map is at `notification+0x18` and describes the
  returned `0x2000` bytes.
- Selector 24 wrapper `0xfffffff009f1ac24` accepts the command queue and
  notification IDs, then calls `0xfffffff009f490f4`.
- The setter stores the derived object at `queue+0x428` and the notification
  object through the slot referenced by `queue+0x430`.

The machine-readable audit is generated by
`tools/a15_ios26/audit_agx_submit_boundary.py`. Its
`notification_queue_identity` record verifies the class string, selector-14
factory path, allocator slot and installed vtable on the exact kernelcache. It
predicts the linked empty-record path reaches backend preparation,
owned-buffer resolution, the empty-record finalizer and normal backend release.

## Bounded v2 contract

1. Reuse the validated owned AGX client, shared buffer and command queue.
2. Require `queue+0x428 == 0` and the object through `queue+0x430 == 0`.
3. Call selector 14 once with 256 entries of 32 bytes.
4. Validate the returned user map, registry ID, notification vtable, map
   address and exact `0x2000` map length.
5. Call selector 24 once with the owned command queue and notification IDs.
6. Require a stable nonzero `queue+0x428`, the same `queue+0x430` slot and the
   exact notification object through that slot.
7. Call selector 25 at most once with the existing zero `0x40` record.
8. Capture cleanup, close the owned connection and stop. Never retry
   automatically.

The probe contains no nonempty packet, GPU MMIO, RTKit command, physical
write, protected-memory write, root replacement, bootstrap or Sileo launch.
